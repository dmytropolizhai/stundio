## Правила чтения документа

- **Факт** — подтверждён источником в репозитории, источник указан в скобках.

## 2. Приоритет: для кого лендинг в первую очередь

1. **S1 — студент RVT на Android.** Самая большая платформа (README:9), единственная, где есть
   виджет — заявленное ценностное предложение (PRODUCT.md «Positioning»), и при этом
   **самый высокий барьер установки** (APK, предупреждение Android). Лендинг здесь даёт
   наибольший прирост: он снимает возражение, которое веб-приложение и GitHub Releases не
   снимают.
2. **S2 — студент на iPhone / desktop.** Тот же JTBD, проще установка, но риск разочарования
   из-за отсутствия виджетов. Нужен честный, короткий, отдельный путь.
3. **S3 — учителя.** Меньше по числу (Г), но высокое влияние: (Г) учитель, которому удобно,
   легитимизирует приложение для группы. Один блок, не отдельная страница.
4. **S4 — новички** — момент внутри S1/S2, влияет на тайминг и на одно сообщение (здания).
5. **S5 — родители** — не проектируем.
6. **S6 — портфолио** — вторично, обслуживается качеством исполнения и футером.

**Почему так (PRODUCT.md, «utility wins»):** при конфликте студенческая польза (скорость
понимания, лёгкость страницы, ясность установки) важнее выразительности для портфолио.
Портфолио-ценность лендинга должна появиться из того, что он безупречно делает работу S1–S2.

### Что это значит для первых 5 секунд

Почти все приходят **по рекомендации, уже зная, что это «расписание RVT»**, на телефоне, часто во
встроенном браузере мессенджера, на неизвестной сети. Значит, за 5 секунд экран 360–390 px
должен ответить на три вопроса, без скролла:

1. **«Это то, о чём мне говорили?»** — название Stundio + «расписание RVT» + реальный визуал
   «сейчас / дальше» (скриншот Day view; виджет — если будет реальный снимок).
2. **«Что это мне даёт?»** — одна строка: следующая пара, кабинет и замены — даже без сети,
   без логина.
3. **«Что нажать на моём телефоне?»** — одна главная кнопка, уже выбранная под устройство
   (раздел 4), и под ней микротекст, снимающий главный страх этой платформы.

Следствия: hero не может зависеть от тяжёлых картинок / шрифтов для понимания (текст и кнопка
читаются до загрузки скриншота); никакой анимации-заставки; дисклеймер «неофициально» —
не в hero, но доступен в один скролл (он отвечает на возражение, а не задаёт тон).

## 4. Android vs iOS / desktop: развилка установки

### Различие (факты)

| | Android | iOS (iPhone/iPad) | Desktop |
| --- | --- | --- | --- |
| Форма | Нативный APK (Capacitor) | PWA через Safari | PWA / сайт |
| Где взять | `stundio.pages.dev/download` → последний APK из GitHub Releases (`functions/download.ts`) | `stundio.pages.dev` в Safari → Поделиться → На экран Домой | `stundio.pages.dev` |
| Виджеты | Да, три (Next Lesson 2×1, Countdown, All-Day 4×2) | Нет | Нет |
| Уведомления | Локальные, из фонового обновления | Web Push, только после добавления на экран Домой | Web Push |
| Обновления | Приложение само проверяет GitHub и предлагает обновиться | Автоматически (веб) | Автоматически |
| Главный барьер | Предупреждение «неизвестный источник» | Найти «На экран Домой»; открыть именно в Safari | Нет (но нужен перенос на телефон) |

### Как лендинг ведёт каждого

- **Определение устройства на клиенте** — тем же способом, что уже в приложении
  (`src/ui/lib/platform.ts`): `/Android/i` в UA; iOS = `/iPhone|iPad|iPod/` или
  `MacIntel` + `maxTouchPoints > 1` (iPadOS); иначе desktop. Логику стоит переиспользовать
  или повторить один в один, чтобы лендинг и приложение не расходились (решение — задача 3).
- **Прогрессивное улучшение, а не развилка-ловушка.** Без JS / до определения показывается
  нейтральное состояние с обеими ссылками. JS только *переупорядочивает*: кнопка своей
  платформы становится главной, другая — текстовой ссылкой «У меня iPhone» / «У меня Android».
  Ошибка определения (планшеты, редкие браузеры, «запросить версию для ПК») не должна
  оставлять человека без нужной ссылки.
- **Android:** главная кнопка «Скачать APK» → `/download`; рядом — 3–4 шага из README и
  объяснение предупреждения Android **до** того, как оно появится. Вторичная: «Попробовать
  в браузере».
- **iOS:** главная кнопка «Открыть Stundio» → `stundio.pages.dev`; рядом — шаги Safari.
  (Г) Если лендинг открыт во встроенном браузере мессенджера или не в Safari, показать
  подсказку «Откройте в Safari» — **требует проверки на реальных устройствах** (раздел 6).
  Явная строка: «Виджеты на главном экране — только на Android».
- **Desktop:** «Открыть в браузере» + QR для переноса на телефон.
- **Уже установлено** (PWA standalone): лендинг не нужен — (Г) но так как лендинг живёт
  отдельно от приложения (`landing/`), этот случай возникает, только если маршрут лендинга
  пересекается с приложением; учесть в задаче 3.

## 6. Открытые вопросы и риски

1. **Куда ведёт `bit.ly/stundio`?** Это единственная ссылка, которую разносит картинка недели и
   текст сообщения (`weekImage.ts`, `share.message`). Если она указывает на веб-приложение,
   лендинг не получит основной органический трафик. Решение — направить bit.ly на лендинг
   (без изменения кода приложения) — нужно согласие автора. **Самый важный вопрос для 2.1.**
2. **Формулировка «Better EduPage experience»** на картинке (`share.image.appLabel`) и в
   сообщении может читаться как связь с EduPage. На лендинге так не писать; передать в 1.3 как
   риск claims.
3. **Нет реального скриншота виджета** в `.github/assets/screenshots/` (есть day, week,
   subjects, settings). Главный аргумент для S1 без визуала — нужен снимок (задача 2.3).
   Мокап «нарисовать виджет» запрещён правилами PLAN.md, если он выдаётся за скриншот.
4. **Встроенные браузеры мессенджеров** (основной вход через ссылку в чате): (Г) загрузка APK и
   «На экран Домой» там могут вести себя иначе. Проверить на реальных устройствах; возможно,
   нужна подсказка «открыть в браузере».
5. **Школьные объявления / плакаты** — канал под вопросом: неофициальный статус может не
   позволить размещение. Не планировать на него, пока автор не подтвердит.
6. **Язык лендинга** (решает 1.3). Входные соображения: школа работает на латышском
   (PRODUCT.md), приложение в LV/EN/RU/UA; данных о распределении языков у пользователей в
   репозитории нет — (Г) значимая доля русско- и украиноязычных студентов. Рекомендация
   1.1: определять по `Accept-Language` / `navigator.language` с явным переключателем,
   LV по умолчанию — **гипотеза**, нужна проверка.
7. **Доля учителей и платформ** неизвестна — нельзя говорить «большинство», «половина» и т.п.
   Предложение: события Plausible на лендинге (клик «Скачать APK» / «Открыть на iPhone» /
   «Для преподавателей»), без нарушения политики приватности (без cookies, opt-out
   сохраняется — README «Privacy»).
8. **Сезонность (Г).** Пик спроса — начало учебного года и смена расписания. Лендинг после
   пика получит меньше трафика по каналу «новички».
9. **Риск доверия.** Любое преувеличение (отзывы, «официальный», округлённые цифры) на
   странице, призывающей ставить APK из неизвестного источника, ударит по главной конверсии.
   Честность — функциональное требование этого лендинга, не только этическое.
10. **PRODUCT.md устарел** («no real users yet», «LV/EN/RU», «no backend» при наличии Functions)
    — источником истины для лендинга считать README (как и сказано в PLAN.md).
