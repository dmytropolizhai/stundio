## Design Specificity Verdict

**LLM assessment:** Stundio's desktop view is a disciplined, high-craft phone app wearing a desktop coat. Its mobile identity ("The Confident Companion") is genuinely authored for RVT students — cool paper ground, unbordered 28px cards, tabular mono times, six pastel subject accents, and honest offline/staleness cues — and the team made three smart desktop adaptations (`SideNav`, widened `--screen-max`, `HomeSide`, and full subject names in `WeekView`). Beneath those three seams, however, the desktop interaction model, spatial math, overlay ergonomics, and secondary screens remain phone-bound: at 1024px `HomeView` crushes the primary schedule to 320px, mouse users have no manual refresh button, interactive surfaces lack `:hover` feedback, `user-select: none` blocks copying text, modals remain floor-anchored mobile drawers, and Onboarding/Pickers/Settings/Subjects stretch phone stacks across widescreen monitors.

## Overall Impression

Stundio already has an enviable design system and a genuinely strong `WeekView` on desktop, which makes the remaining mobile-only assumptions stand out sharply. The single biggest opportunity is **finishing the desktop interaction & layout contract**: fixing the 1024px Home column crush, adding pointer/keyboard fundamentals (manual refresh, `:hover`, selectable text, `Esc`, safe arrow keys), centering `BottomSheet` on desktop, and constraining/fixing Onboarding and Pickers.

## What's Working

1. **Disciplined light/dark semantic token architecture (`src/ds/tokens/dark.css`, `src/index.css`):** Re-pointing semantic aliases while preserving pastel subject accents via `readableInk()` keeps desktop monitors crisp and legible without color drift.
2. **`WeekView` desktop density (`src/ui/screens/week-view/week-view.tsx:49`, `week-grid.tsx`):** Expanding 3-letter codes to full names, multi-period `grid-row` spanning, long-break dividers, and clickable day headers make `WeekView` the strongest desktop screen.
3. **Honest Tauri Linux & offline platform awareness (`src/lib/platform/`, `notifications-section.tsx`, `about-section.tsx`):** Hiding Android-only APK/alarm controls on desktop while surfacing Linux notification portal and update hints shows real platform respect.

## Priority Issues

### 1. [P0] HomeView 3-column layout crushes the primary schedule to 320px at 1024px desktop
- **What:** At `1024px` (`useLayout() === "desktop"`), `SideNav` (`232px`) + `px-10` (`80px`) + `gap-x-10` (`40px`) + `HomeSide` (`352px`) leaves only **`320px`** for the primary `HomeView` column (`src/ui/screens/home-view/home-view.tsx:381–386`, `src/ui/components/SideNav.tsx:33`) — narrower than an iPhone SE and narrower than `HomeSide` itself. Two-subgroup `lesson-pair` cards collapse to `154px` each.
- **Why it matters:** 1024px–1280px is the real width of 13" laptops at 125–150% scaling, school lab monitors, and tiled Linux desktop windows. The primary "what's on now" column must never be narrower than its secondary sidebar.
- **Fix:** Only mount `HomeSide` at `≥1280px` (a 4th `"wide"` tier / `xl:`), OR at `1024px–1279px` narrow `HomeSide` to `18rem` (`288px`) with `px-6 gap-x-6` so the main column stays `≥420px`.
- **Suggested command:** `$impeccable adapt`

### 2. [P0] No manual refresh affordance for mouse/trackpad users on Home, Week, or Changes
- **What:** `PullToRefresh` (`src/ui/components/PullToRefresh.tsx:34–55`) is touch-only, `SyncStatus` (`src/ds/components/ui/sync-status.tsx:81–92`) only renders `onRetry` when `state === "failed"`, and clicking `SyncBadge` in `idle`/`synced` state only toggles the timestamp.
- **Why it matters:** Checking for newly published substitutions is a core workflow. Desktop users cannot manually sync from any schedule screen without digging into Settings → Data → Sync or reloading the browser/window.
- **Fix:** Show an `IconButton icon="refresh-cw"` in desktop schedule top bars (or in the `SideNav` footer alongside `ClassBadge` + `SyncBadge`), and allow triggering `refresh()` from `SyncBadge` whenever not currently syncing.
- **Suggested command:** `$impeccable harden`

### 3. [P0] `ChangesView` arrow keys hijack text cursor inside search input & controls
- **What:** `src/ui/screens/changes-view/changes-view.tsx:223–231` binds `ArrowLeft`/`ArrowRight` to `onDateChange(addDays(date, ±1))` on the outer wrapper without checking `e.target !== e.currentTarget` or ignoring form controls (unlike `HomeView:350` and `useSwipePager:112`).
- **Why it matters:** Typing a class code in `ChangesAllClasses` search and pressing Left/Right arrow to fix a typo silently jumps the entire screen to the previous/next day.
- **Fix:** Ignore keyboard events originating inside `input, textarea, select, [role="radiogroup"], [role="dialog"]`, and migrate `ChangesView` to `useSwipePager` + `stepSchoolDay` so Friday steps to Monday instead of Saturday.
- **Suggested command:** `$impeccable harden`

### 4. [P0] Invisible light-mode text, malformed CSS, & 1,880px full-bleed controls on Desktop Onboarding
- **What:**
  1. `src/App.tsx:171,186`: onboarding picker subtitles use `text-white/72` on `bg-card` (**0:1 white-on-white** in light mode).
  2. `src/ui/screens/onboarding-persona/onboarding-persona.tsx:108`: `<h1>` omits `text-white`, rendering dark `#0b0c10` text over dark gradients in light mode; line 67 has malformed CSS `var(--spacing(8))`; lines 36–42/105 use banned raw hex (`#0e0f14`, `#ffb552`, `#0b0c10`) and stock `amber-*` colors.
  3. `OnboardingLanguage`, `OnboardingIntro`, `SubgroupPicker`, and onboarding picker headers omit `max-w-screen mx-auto`, stretching full-width buttons to 1,880px on 1080p monitors.
- **Why it matters:** Every first-time desktop visitor, student on a lab PC, or portfolio reviewer hits these screens first.
- **Fix:** Fix `App.tsx:171,186` to `text-muted`, add `text-white` and DS tokens to `OnboardingPersona` (and fix `--spacing(8)` without `var()`), and constrain all onboarding screens to a centered `max-w-[480px]` column on desktop.
- **Suggested command:** `$impeccable polish`

### 5. [P1] Desktop pointer & text fundamentals missing (`user-select: none`, zero `:hover`, hidden scrollbars)
- **What:** `src/index.css:491–492` applies global `user-select: none` on `body` with zero `select-text` overrides; interactive `Card`, `LessonCard`, `WeekGrid` cells, `SettingsRow`, and `DatePicker` have zero `:hover` feedback; `no-scrollbar` hides vertical scrollbars in `settings-view.tsx:92`, `class-selector.tsx:84`, `teacher-picker.tsx:53`, and `bottom-sheet.tsx:136`.
- **Why it matters:** Desktop users cannot copy room numbers or school notes, get no hover affordance distinguishing clickable vs static cards, and lose scrollbar position cues on long sheets like `CustomizationSheet`.
- **Fix:** Gate `user-select: none` and `no-scrollbar` behind `@media (pointer: coarse)` (or allow `select-text` on lesson/note content), and add subtle `@media (hover: hover)` hover states to all interactive cards, rows, and week cells.
- **Suggested command:** `$impeccable polish`

### 6. [P1] `BottomSheet` remains a floor-anchored mobile drawer on desktop (and shifts off-center when `SideNav` is absent)
- **What:** `src/ds/components/ui/bottom-sheet.tsx:88–140` anchors sheets to `bottom-0` with a touch grab-handle on 1080p/1440p monitors, applies `tablet:left-21 desktop:left-58` unconditionally even when `SideNav` isn't mounted (onboarding/pickers), hides scrollbars (`no-scrollbar`), and hardcodes English `"Close"`/`"Details"`.
- **Why it matters:** Every lesson inspection, setting choice, and customization flow feels stranded at the bottom of the desktop viewport and shifts 116px off-center during pickers.
- **Fix:** Center `BottomSheet` vertically on `desktop:` (`rounded-2xl max-h-[85vh]`), hide the grab handle on desktop, drive the sidebar offset from a `--sidenav-offset` CSS var set only when `SideNav` is mounted, restore scrollbars, and localize `"Close"`/`"Details"`.
- **Suggested command:** `$impeccable adapt`

### 7. [P1] `HomeSide` wrong `day` prop bug, temporal overload, and unsticky right column
- **What:** Clicking a `ChangesLessonCard` in `HomeSide` (always *today*'s change) while browsing another day opens `<LessonSheet lesson={open} day={day} />` (`src/ui/screens/home-view/home-view.tsx:413–415`) with the *browsed* `day` instead of `today` (wrong fallback building). Meanwhile, Home simultaneously displays 4 temporal frames (browsed `HomeBrief` + today `DayGlance` + browsed `DayLessonList` + today `HomeSide`), shows `DayTomorrow` even when already viewing tomorrow, and leaves `HomeSide` unsticky.
- **Why it matters:** Produces subtly wrong building data in `LessonSheet`, causes cognitive load failure #1 (Single focus), and leaves a blank 352px void while scrolling a busy day.
- **Fix:** Store `{ lesson, day }` in `HomeView`'s `open` state so `HomeSide` passes `today`; hide `DayTomorrow` when `date === nextDate`; make `HomeSide` `sticky top-6` aligned below `HomeTopBar` with explicit `"Today"` framing.
- **Suggested command:** `$impeccable clarify`

### 8. [P1] Keyboard focus, contrast, & Teacher Mode truncation defects
- **What:**
  1. `SubjectNoteSheet.tsx:48`: `outline-none` on `<textarea>` with zero focus replacement; `src/index.css:541` omits `textarea` and `[tabindex]` from global `:focus-visible`.
  2. `SettingsRow` (`settings-row.tsx:33`): `tone === "alert"` sets `text-danger/12` (12% opacity foreground!) instead of `bg-danger/12 text-danger`, hiding Linux desktop notification failure alerts.
  3. `ClassSelector` / `TeacherPicker` (`App.tsx:256–294`): drop `max-w-screen` (1,880px rows under an 880px `TopBar`) and ignore `Esc`.
  4. Teacher Mode desktop `WeekView` (`week-view.tsx:180`, `week-grid.tsx:377`): formats label as `"${subjectName} (${classNames})"` with single-line `truncate`, clipping off the class code even on 2-period spans — reversing the group-first scanning rule.
- **Why it matters:** Breaks WCAG focus visibility and alert contrast, strands keyboard users in pickers, and breaks Teacher Mode week scanning on desktop.
- **Fix:** Add `textarea` to `:focus-visible` and remove bare `outline-none` in `SubjectNoteSheet`; fix `SettingsRow` to `bg-danger/12 text-danger`; constrain pickers to `max-w-screen` + bind `Esc`; put `classNames` first (or allow `line-clamp-2` on desktop spanning cells) in Teacher Mode `WeekView`.
- **Suggested command:** `$impeccable audit`

## Questions to Consider

1. **Should `HomeSide` mount only at `≥1280px`?** Right now, forcing 3 columns (`SideNav` + `Home` + `HomeSide`) into `1024px` makes the primary schedule narrower than a phone (320px vs 380px).
2. **Should `ClassBadge` + `SyncBadge` (with a manual Refresh button) move into the `SideNav` footer on desktop?** Every schedule tab currently repeats that cluster in its `TopBar` while `SubjectsView` and `TransitView` lose it completely.
3. **Should `DESIGN.md` get a formal Desktop Addendum?** The codebase already ships `SideNav`, `Popover`, `TooltipProvider`, `desktop.css`, and `HomeSide` for web + Linux Tauri — keeping `BottomSheet` floor-anchored with a touch handle is loyalty to a mobile-only rule that no longer fits the desktop shell.
4. **In Teacher Mode on Desktop `WeekView`, should the class code lead (`"DP3-1 · Objektorientētā..."`) or wrap onto 2 lines?** Putting the class code in parentheses at the end of a truncated line defeats the teacher's primary scan axis.
